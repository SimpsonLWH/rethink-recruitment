## 1. Status is derived, never hand-written

The status layer does not trust wording or environment flags. It combines two independent things:

1. recent `AiRun` rows from the repository (`getRepository().getRecentAiRuns(50)`);
2. the empty-or-not list of captured live artifacts in `LIVE_EVIDENCE`.

Rules implemented in [`src/lib/ai/status.ts`](src/lib/ai/status.ts):

| Status | Meaning |
| --- | --- |
| `live-with-evidence` | A `LIVE` `AiRun` row exists **and** a matching redacted `LIVE_EVIDENCE` entry exists for the same surface. |
| `implemented-not-run` | The code exists, but no live run with captured evidence exists. This deliberately includes a live run made without a captured artifact, and captured evidence without a matching live run. |
| `demo-fallback` | Only deterministic fallback rows have run, or no live evidence exists. This is the honest runtime mode in this checkout. |

`getAiStatusState()` returns one state per surface plus an overall mode. If the database is unreachable it returns a safe no-db state and still claims nothing live. A configured API key alone can never produce `live-with-evidence`; only a real run plus a captured artifact can.

Verify the pure rules (no database, no network, no keys):

```bash
cd recruitment-app
npx vitest run src/lib/ai/status.test.ts
```

## 4. What was measured — fallback only

The only AI output this audit measures is deterministic fallback output, produced by running `scripts/ai-audit.ts` on a seeded database and written to `audit/fallback-samples.json`. The file is generated, never hand-written: if it is absent, the script has not been run in that checkout. That artifact contains:

- `extract`: sample input, deterministic highlights, and grounding checks (source quote containment, URL literalness, absence of a provenance field);
- `tailor`: deterministic suggestions, the local rewrite path's note when it declines a claim, and a per-suggestion source-vs-output comparison with token-Jaccard and bigram-Dice similarity plus number/URL preservation checks;
- `ask`: the question, the grounded answer, and its cited source fact IDs;
- `feedRules`: the required example recruiter preference and its `rules-v1` parse, plus a protected-characteristic example that refuses only the offending clause and continues with the rest.

What this measurement does and does not support:

- It supports statements like "the fallback is deterministic, keeps quoted text grounded in the input, cites only known facts, and does not add URLs."
- It does **not** support any statement about model quality, accuracy, speed, safety, or superiority. No model output was produced.
- The fallback artifact contains no environment values, API keys, tokens, cookies, or authorization headers.

The script never imports `callNemotron`, `callGemini`, or the HTTP helper. Running it cannot spend quota or contact a provider. If the database is not seeded, it exits with a clear error instead of pretending fallback output is live data.

- `LIVE_EVIDENCE` in [`src/lib/ai/live-evidence.ts`](src/lib/ai/live-evidence.ts) is `[]` in this checkout.
- No live run has been recorded, and no redacted live capture exists under `audit/live/`.

## 6. Gemma — explicitly not implemented

No Gemma integration exists: no model ID, client, route, prompt, schema, or validation. **Gemini and Gemma are different model families**, so the existing Gemini client is not a Gemma integration.

Critique: adding Gemma would require a new model client, prompt set, validation, and evidence surface with no demonstrated task gain. The existing model integrations still lack live evidence, so adding another unrun integration would be badge padding. No Gemma model ID exists in the code, and no Gemma claim is made.

## 7. Modal — optional batch, not deployed

The Python batch in `modal/` is optional, CPU-only, and not a language-model integration. It is **not deployed, not remote-run, and not on the runtime path**. The demo's advisory fit briefs come from the local TypeScript implementation. No Modal tokens were used, no deployment was created, and no remote artifact exists in this checkout. See `modal/README.md` for the exact gated commands.

## 8. Non-claims and limits

This audit does not claim, and should not be read as claiming:

- that any live model integration works — no live request was made in this checkout;
- that any model output exists or has been evaluated — none was captured;
- that one model is better than another — no comparative measurement was made;
- any accuracy, latency, cost, safety, or quality number;
- that a configured API key is evidence — configuration is only readiness, never a live run;
- that passing mocked HTTP tests proves provider behavior;
- that the fallback speaks for the live path's output.

If real keys and quota are approved later, record live results through the process in `audit/live/README.md` and let `getAiStatusState()` derive the labels. Do not edit this document into a live claim first.
