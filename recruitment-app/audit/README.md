# AI audit — measured fallback output only

This directory holds audit artifacts for Rivet's AI-adjacent surfaces. The rule for everything here: **a file may only describe what was actually executed.** No hypothetical model output, no unmeasured claims, no keys.

The repository-level summary is [AI-AUDIT.md](../AI-AUDIT.md).

## Current state

- No live model run has been recorded in this checkout.
- No live model output has been captured.
- Only deterministic fallback output and the local rules parser were measured.
- [`src/lib/ai/live-evidence.ts`](../src/lib/ai/live-evidence.ts) exports an empty `LIVE_EVIDENCE` array. While that list is empty, nothing in this directory may be presented as live evidence.

## Files

| Path | What it is |
| --- | --- |
| `fallback-samples.json` | Generated by [`scripts/ai-audit.ts`](../scripts/ai-audit.ts). Deterministic fallback output for extract, tailor and ask, the required recruiter preference plus a protected-characteristic example, and a source-vs-output comparison for tailoring. |
| `live/` | Future redacted live captures, indexed from `LIVE_EVIDENCE`. It contains only [`live/README.md`](live/README.md) today. |

`fallback-samples.json` is committed as actual fallback evidence and can be regenerated with the command below; never hand-write it. If it is absent, the fallback audit has not been run in this checkout. Any live capture committed in the future must go under `live/` and follow the rules there.

## Run the fallback audit

From `recruitment-app/` (the database must be seeded, and `src/lib/feed.ts` must exist):

```bash
npm run seed
npx tsx scripts/ai-audit.ts
```

The script:

- never imports `callNemotron`, `callGemini`, or the HTTP helper, so it cannot make a model or network request;
- loads the seeded **Aino Vikström** candidate and the **Northwind Labs · Product Engineer** role through `getRepository()`;
- calls only deterministic local functions (`extractHighlightsLocally`, `suggestTailoringLocally`, `answerFromFactsLocally`, `parseFeedPreferenceRules`);
- writes [`fallback-samples.json`](fallback-samples.json) as pretty JSON and prints a short summary;
- fails with a clear message when the database is not seeded. A missing database or missing feed module is an error, **not** fallback data.

## What the artifact contains

- `generatedAt` and a note stating that every output is deterministic fallback and no live model was called.
- `fallbacks.extract`: the sample input, deterministic highlights, and grounding checks (source quote containment, URL literalness, no provenance field).
- `fallbacks.tailor`: deterministic suggestions plus the local rewrite path's note when it declines a claim, and a per-suggestion source-vs-output comparison with token-Jaccard and bigram-Dice similarity plus number/URL preservation checks.
- `fallbacks.ask`: the question, the grounded answer, and its source fact IDs.
- `fallbacks.feedRules`: the required recruiter preference example and a protected-characteristic example, each with its `rules-v1` parse (criteria, rejected, unparsed).
- The script reads and writes **no environment values, API keys, tokens, cookies, or authorization headers**. Do not add any.

## Claim discipline

- Fallback output is not model output. It demonstrates determinism and grounding, not live model quality, latency, or accuracy.
- A live claim requires **both** a real `LIVE` `AiRun` row and a matching redacted `LIVE_EVIDENCE` entry. See [`live/README.md`](live/README.md).
- The status layer [`src/lib/ai/status.ts`](../src/lib/ai/status.ts) derives its labels from those two sources; do not hand-write a live badge or a live claim into docs.
- To verify the pure status rules:

  ```bash
  npx vitest run src/lib/ai/status.test.ts
  ```
